# P1.9 / P1.9.1 search-memory backport

## Summary

Backported the RAM-related implementation from nilesh-kumar-gupta/imgsearch through
`c797888`. The destination previously matched upstream `92bf2e6` plus its LICENSE.
Faces, people search, near-duplicate grouping and phone-batch features are excluded.

## Changes

- Search uses `SiglipTextEmbedder`: only the SigLIP text tower, CPU float32, and the
  checkpoint SentencePiece tokenizer. Image indexing keeps the full model on MPS.
- Added `TextEmbedder`, query device/dtype settings, Ollama `num_ctx`, memory benchmark
  and query-vector equivalence commands, plus upstream tests.
- Default rewrite model is `gemma3:4b`, context 4096, with the P1.9.1 article prompt fix.
  Pull it with `ollama pull gemma3:4b` before running search; no model was downloaded
  or production bot restarted during this backport.
- Source commits: `b4b2717`, `25c3b8b`, `212c6b7`, `50b4a5b`, `e43934a`, with final
  source documentation through `c797888`. Core model/memory code matches upstream.
- Preserved upstream P1.9/P1.9.1 reports and evaluation evidence (whitespace normalized). Those
  reports describe the source project's database, environment and operations.

## Reported memory and limitations

Upstream reports total search footprint + Ollama residency of 6.89 -> 5.13 -> 2.73 GB
(about 60% less than the original baseline). Search process: 2.24 -> 0.48 GB; Ollama:
4.65 -> 2.25 GB. These are upstream observations, not a local RAM benchmark.
The latest source evals include faces/dedup and a different library, so their recall
figures must not be presented as measurements of this narrower backport.

No photos, S3 objects, credentials or real photo database were accessed. Tests use
fake providers and temporary data; SigLIP equivalence tests use a tiny random model.

## Validation

The imported CLI registration test originally read the real project config and
failed without IMGSEARCH_STORAGE_ROOT. It now passes its existing temporary config
explicitly through --config, consistent with the other isolated tests.
The sandbox cannot expose Metal to the existing caption module; the suite therefore
runs with native GPU access. Final validation results are recorded below.

- `uv run --locked pytest -q`: **553 passed** in 17.31 seconds.
- `ruff check .`: all checks passed.
- `git diff --check`: clean.
- No full-size model inference, local RAM benchmark or retrieval eval was run.
