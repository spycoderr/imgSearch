# M5 report: hybrid search, fusion, `search()` and CLI

2026-10-20

## Summary

- **Fusion.** `rrf_fuse(rankings, k)` (`imgsearch/search/fusion.py`) is a plain function:
  score = Σ 1 / (k + rank) over the rankings an image is in. Ties go to the best single
  rank, then `image_id`. `k` comes from `search.rrf_k` (60).
- **Search entry point.** `Searcher` (`imgsearch/search/hybrid.py`) is built once by
  `open_searcher(config, conn)`, which loads SigLIP and creates the `OllamaRewriter`. Then
  `searcher.search(query, k=None, rewrite=True, signals=None)` is called once per query.
  - The flow: rewrite, then the vector retriever on `english` and the text retriever on
    `english` + `original`, each asked for `search.per_retriever_k` (50), then RRF, then the
    top `k` (default `search.top_k`, 5).
  - `rewrite` and `signals` are the switches for M7's ablations.
  - It returns a `SearchResponse`: the `ParsedQuery` that was searched, whether the rewrite
    was on, the signals used, the `Result`s and the timings (rewrite, retrieval, total).
- **Interface changes.**
  - `Result` gains `orig_relpath` and `score` (the fused score).
  - `ParsedQuery` gains `rewrite_error`, which the rewriter sets when it falls back, so the
    CLI can say the rewrite was skipped.
  - Both are recorded in the plan.
- **W1, the rewriter guard.** `date_range` is kept only if the query has a digit-based year
  or a numeric date. The prompt has one `{today}` placeholder, which code fills with today's
  date. "kal wali shaadi ki photos" was added to `eval/rewrite_examples.yaml`, and all 21
  examples were re-run.
- **CLI.** `imgsearch search "..." [--k N] [--no-rewrite] [--signals vector,text]` prints
  what was searched, then for each result: rank, fused score, relpath, matched signals with
  their ranks, and a short caption. Then it prints the timings.
  - **W4:** `search-vec` and `search-text` were **removed**. `search --signals vector
    --no-rewrite` and `search --signals text --no-rewrite` do the same, and use the one printer.
  - With `--signals text --no-rewrite`, no model is loaded and Ollama isn't needed.
- **W3:** the README says not to search during a caption run.
- **Checks.** `uv run pytest` passes: 184 tests, 38 of them new. The 4 tests of the removed
  printers were deleted. `ruff check`
  and `ruff format --check` are clean.

**Where hybrid beats a single signal:**

- **"The Road Not Taken"**: vector only has neither poem page in its top 5 (they are 6th and

- **"samundar mein masti karta bachcha"**: text only finds nothing relevant. The captions say

- **"क्रिसमस ट्री के सामने बच्चा"** and **"boy in front of a christmas tree"**: text only has
  the third Christmas photo at 5 and 4. Hybrid has it at 3.

**Where hybrid is worse than a single signal:**

- **"safed kutta carpet pe baitha hua"**: vector only has both carpet-dog photos 1st and
  2nd. In hybrid the second one drops to 4th, because text ranks other white-dog photos
  higher ("white dog" matches every dog caption).
- **"pigeons on the street"**: vector only has both pigeon photos 1st and 2nd. Hybrid puts a

No query had hybrid better than **both** single signals. In this small library, one of the
two signals is nearly always enough on its own. Hybrid mostly protects against whichever
signal fails on a given query.

Other things seen:

- **The rewriter changed 2 of the 8 English queries** (5 English, 3 text-in-image). It added "a" to "boy in front of a christmas
  tree" and capitalised "Dubai". M6's rule is that English is copied unchanged, so this is a
  small break of that rule. It changes nothing in the results here: SigLIP lowercases, and
  "a" is a stopword. M7 should count it.
- **Vector-only filler.** When text finds only 1–2 images, the rest of the top 5 is the
  vector ranking's tail. For example, "birthday cake" brings the candy-list photos at 3–5,
  and "waves on the beach" brings notebook pages. Nothing filters on score (RRF uses ranks
  only), so the top 5 is always full when the vector signal runs.
- **Near-duplicates** fill the top 5 (the white-dog pair, the Christmas series, the
  assignment sheets). This is the P6 baseline already noted for M7.

## Changes from the plan

These are recorded under "Changes during build" in the plan doc.

- **`search()` is a method of a `Searcher` that is built once.** It is
  `open_searcher(config, conn, signals, rewrite)`, then `searcher.search(query, k, rewrite,
  signals)`, which returns a `SearchResponse`, not a bare `list[Result]`. This is so models
  load once per process (M7 calls it hundreds of times), and so callers see what was
  searched and the timings.
- **`Result` gains `orig_relpath` and `score`.** `orig_relpath` is for the CLI and for a
  later "send original". `score` is the fused RRF score. Paths in `Result` are relative, as
  stored in the DB.
- **`ParsedQuery` gains `rewrite_error: str | None`.** The rewriter still never raises (M6).
  On fallback it now says why, so the CLI and the eval can tell a failed rewrite from an
  English query passed through unchanged.
- **Rewriter date guard (W1).** `date_range` is set to None unless the query contains a
  year from 1900 to 2099, or a numeric day/month such as `15/08`, `3-4-21` or `15.8.19`.
  Digits in any script count (२०१९). Dates written with a month name ("15 August") aren't
  recognised and are dropped.
- **`{today}` placeholder.** The prompt contains `{today}` exactly once. `RewriterConfig`
  rejects a prompt without it, and code fills it in with today's ISO date.
- **W4: `search-vec` and `search-text` were removed**, along with `candidate_lines` (cli.py)
  and `best_snippet` (text.py), which only they used. The printer is `response_lines` in
  `imgsearch/search/show.py`. The text-match snippet with `[ ]` is no longer shown;
  the result shows the caption instead.
- **Fusion ties.** Scores are compared rounded to 12 decimal places, so sums that are equal
  on paper but differ in the last bit count as ties. Each image's terms are summed in rank
  order.

## Flags

- **"kal" is translated as "previous year's".** The date guard drops the invented date, but
  the English is still wrong, so the vector side searches for the wrong thing.
- **English isn't always copied exactly.** Of the 8 English queries, one gained an "a" and
  one was capitalised. Neither had any effect here.
- **Hybrid can be worse than vector alone** when the query's words match many captions
  ("white dog", "street"). M7's ablations will show how often.
- **The top 5 is always full.** Vector always returns 50, so weak matches fill the top 5.
  A score floor, or a minimum number of matching signals, would be a later change, measured
  in M7 first.
- **Memory.** Search needs about 2.2 GB in its own process plus 4.6 GB in Ollama. The
  README says not to search during a caption run (W3).
- **The query set was chosen after reading the captions**, so its results are optimistic.

### For M7

- Build once with `open_searcher(config, conn)`, then call
  `searcher.search(query, rewrite=..., signals=[...])` for each ablation. `signals=None`
  means both.
- `SearchResponse.query` is what was searched, and `query.rewrite_error` is set when the
  rewrite fell back. `Result.signals[name] = (rank, score)` for each signal that matched.
- `rewrite=True` calls Ollama each time, about 1.6 s per call warm. 40 queries × 3 signal
  settings × 2 rewrite settings is about 2 minutes of rewriting. The rewrite is
  deterministic within one Ollama version, so M7 could cache it per query if that helps.
- Items to include: "kal wali shaadi ki photos" (wrong English), जयपुर → Jodhpur (W2), the
  English-changed cases, and queries where text words match many captions ("white dog").
