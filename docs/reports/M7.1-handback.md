## M7.1 (single phase)

M7.1 is done. `imgsearch search` now defaults to vector + rewrite, set by
`search.default_signals: [vector]` in `config.yaml`, and `search.per_retriever_k` is 10.
Committed on `main` up to `c180863`, not pushed. 222 tests pass (7 new) and ruff is clean.

**What changed**
- **One default for every caller:** `open_searcher` and the `search` command read
  `search.default_signals` when no signals are given. `--signals vector,text` still runs
  hybrid.
- **The eval is unaffected:** it now asks for both retrievers explicitly. Otherwise the new
  default would have quietly dropped text search from its 7 configurations.
- **Docs:** "Decisions after the MVP" at the end of `docs/mvp-summary.md`, the README search
  section, and the plan. `docs/eval/baseline.md` is untouched.

**Eval re-run** (`eval/runs/20261020-230042`):
- vector+rw: 1.00 / 0.98 / 0.99, same as the baseline.
- hybrid+rw: 1.00 / 0.93 / 0.91, same as the k = 10 experiment. Every metric in every group
  matches.
- One top-5 list differs, at a rank-5 non-expected photo. The rewriter added "a" to
  "flock of pigeons on a road". That happens in every run where Ollama starts cold, and not
  when the model is already loaded. So rewrites aren't fully repeatable within one Ollama
  version, contrary to M6's note. Metrics are unaffected.

**Real searches** (full output in `docs/reports/M7.1.md`):
- English "boy in front of a christmas tree" and Hindi "पढ़ाई की मेज़ पर किताबें": both modes

- Hinglish "Jaipur ka kila": vector alone returns fort and palace photos but puts the
