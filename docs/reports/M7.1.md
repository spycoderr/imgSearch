# M7.1 report: default search signals and `per_retriever_k`

2026-10-20

## Summary

The user decided both changes after the M7 review. Summary of what changed:

- **`search.default_signals: [vector]`.** The key is in `config.yaml` and `SearchConfig`.
  Each item must be `vector` or `text`, listed once, and the list can't be empty.
  - `open_searcher(config, conn, signals=None)` uses it, and so does `imgsearch search`
    when `--signals` isn't given. `--signals vector,text` still runs hybrid.
  - The default search is now vector + rewrite.
- **The eval's configurations are unchanged.** `eval_searcher` now calls
  `open_searcher(..., signals=SIGNALS)`. Without that, the new default would have dropped
  the text retriever from the eval.
- **`search.per_retriever_k: 10`** (was 50).
- **Docs:**
  - "Decisions after the MVP" at the end of `docs/mvp-summary.md`.
  - README "Search (M5)" section.
  - Three M7.1 entries under the plan's "Changes during build".
  - `docs/eval/baseline.md` is untouched.
- **Checks.** `uv run pytest` passes: 222 tests, 7 new. Ruff is clean. The new tests use no
  models: the config default is set to `[text]`, or `--signals text` overrides `[vector]`.

What the six runs show:

- **Christmas tree and study table:** both modes give the same top 3–4, with the order
  shuffled slightly. Rank 5 is weak in every case.
- **"Jaipur ka kila":** vector alone returns Amber Fort trip photos: people on the fort wall
  and courtyards. But the fort panorama, `IMG_20161102_112321`, is only vector #6, outside
  the top 5. Hybrid ranks it 1st, because its caption says "Amber Fort in Jaipur".
  - This is the kind of place-name query where text search helps.
  - It isn't in the eval set: the eval's `dv-jaipur-fort` uses the Devanagari form, which
    the rewriter misspells.
- Timing: warm queries take 1.8–2.2 s in both modes; model load is 5.4–6.3 s per command.

## Changes from the plan

Recorded under "Changes during build" (the M7.1 entries):

- The default signals come from config. This changes query-flow step 3: the text retriever
  now runs only when asked.
- `per_retriever_k` 10, where the plan says "nearest 50".
- Captions run last in P2.

## Flags

- **Rewrites change with Ollama's state.** A cold model (just loaded) and a warm one gave
  different rewrites of the same English query in the same version. The effect seen is
  small (an added "a"), but an eval run isn't byte-for-byte repeatable. Compare runs by
  their metrics. Both kinds of run gave the same metrics here.
- **Place names favour hybrid.** The eval doesn't measure this well (2 `place` queries). The
  extra small-text and place queries recommended for P2 should include Latin-script place
  names, such as "Jaipur ka kila" and "Amber Fort".
- `cli.py` is now 217 lines (the "Should" is about 200).
