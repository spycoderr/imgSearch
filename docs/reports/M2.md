## Changes from the plan

Recorded under "Changes during build" in the plan doc (the M2 entries):

- **Text settings.**
  - New config key: `models.embedder.text_max_length: 64`.
  - Query text is lowercased and tokenized with `padding="max_length"`, `max_length=64`,
    `truncation=True`.
  - Source: the model card is silent; these come from the transformers SigLIP2 docs and
    modeling code.
  - The checkpoint's `model_max_length` is about 1e30 and its tokenizer doesn't lowercase,
    so both are done explicitly.
  - The `"This is a photo of {label}."` template is not used: the docs give it for zero-shot
    classification, not retrieval.
- **No batching.** One image per call, as decided in M0.
- **Test injection.** `EmbedStage(config, make_embedder=...)` follows the M3 convention (S4).
  - The default builder `load_siglip` imports transformers and torch lazily, and `unload()`
    imports torch lazily (S1).
  - `import imgsearch.cli` loads neither, checked by a test.
- **Retriever.** `VectorRetriever(conn, embedder, embedder_config)`.
  - Score is cosine similarity, higher is better.
  - Ties are broken by `image_id`.
  - Only the configured model's rows are ranked.
- **`stages.embed` is now `"2"`.** It was bumped once for acceptance item 10. The vectors are
  identical.

## Flags

- **Panoramas are squashed.** The fixed-resolution checkpoint resizes every derivative to
  384×384. The 6203×507 panorama is squashed about 12:1.
- **Scores are small.** Raw cosine similarities are about 0.0–0.18, normal for SigLIP, which
  applies a learned logit scale. Don't threshold them; RRF uses ranks only.
- **Harmless load warning.** transformers warns that the checkpoint config's
  `bos_token_id`/`eos_token_id` (49406/49407) are outside the vocabulary range. Text inputs end
  with eos id 1 from the tokenizer, so this doesn't affect embeddings.
- **Near-duplicates fill the top results.** They take adjacent ranks with almost equal scores
  ("a building at night" #1 and #2 both score 0.0774; the notebook pages; the beach pair).
  This is the P6 dup-group problem.
- **`--k`, not `-k`.** The CLI option is `--k`, matching `search-text`. My phase A hand-back
  wrongly said `-k`.
- **The test now bumps relative to config.** `test_rerun_with_new_version_replaces_vectors`
  first hard-coded `"embed": "2"`, which broke when the config moved to `"2"`. It now bumps to
  `<current>-bumped`.
