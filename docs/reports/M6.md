# M6 report: query rewriter

2026-10-20

## Summary

`OllamaRewriter` (`imgsearch/models/rewriter.py`) implements `QueryRewriter.rewrite(query) ->
ParsedQuery` through Ollama's `/api/chat`. It sends a JSON-schema `format` and temperature 0,
validates the reply with pydantic, and falls back to the query as given, logging a warning, on
any failure. `imgsearch rewrite "..."` prints the parsed JSON and the time taken. It is not yet
wired into `search()`; that is M5.

Following supervisor decision Q8, three models were compared on the 20 example queries with the
prompt unchanged. **`qwen2.5:7b` was chosen**: 15 correct, 4 minor, 1 wrong, with a warm median
of 1.67 s. `qwen2.5:3b` and `gemma3:4b` were removed with `ollama rm`. Ollama was upgraded from
0.17.4 to 0.40.6, with the user's approval, because 0.17.4 couldn't pull `gemma3:4b`.

`uv run pytest` (150 tests, 16 of them M6's), `ruff check` and `ruff format --check` pass.
Phase A was `3d2a506`, rebased onto `main` (`d343618`) and merged fast-forward.

### Model comparison (Q8)

All three models ran on Ollama 0.40.6 with the same prompt and settings, one model loaded at a
time. Each output was scored by hand against `expect`:

- **correct:** `english` keeps the query's meaning, with nothing added, dropped or
  mistranslated, and `people`, `place` and `date_range` have no errors.
- **minor:** `english` keeps the meaning but is awkward or leaves a relation word untranslated
  (papa, mummy, dadi), or `people` or `place` has an error.
- **wrong:** `english` adds, drops or mistranslates content, or a date is invented.

## Changes from the plan

These are recorded under "Changes during build" in the plan doc.

- **The rewriter model is `qwen2.5:7b`**, not `qwen2.5:3b` (Q8). It uses about 4.6 GB while
  loaded, against 2.1 GB for the 3b.
- **Ollama was upgraded from 0.17.4 to 0.40.6** (`brew upgrade ollama`, then
  `brew services restart ollama`). On 0.40.6 the `/api/chat` request shape is the same
  (checked against docs.ollama.com/api/chat), and the tests pass unchanged.
- **New config keys** under `models.rewriter`: `timeout_s: 30` and `prompt`.
- **`original` is not in the schema sent to the model** (Q7, accepted). Code sets it to the
  exact input; a test checks that a model-supplied `original` is ignored.
- **`OllamaRewriter(config, client=None)`** takes an optional `httpx.Client`, which the tests
  use to pass a `MockTransport`.
- **`date_range` is `{start, end}` in the model schema.** These are ISO dates, validated as
  dates and converted to the `(start, end)` tuple of `ParsedQuery`. An invalid date makes the
  whole reply fall back.

## Flags

- **Outputs change across Ollama versions.** After the upgrade, 13 of the 20 `qwen2.5:3b`
  rewrites differed from phase A (on 0.17.4), with the same model and prompt. The 5 English
  queries stayed the same. Outputs are repeatable within one version. Re-check the examples
  after any Ollama upgrade.
- **#13 invents a place.** `qwen2.5:7b` turns जयपुर (Jaipur) into "Jodhpur", in both `english`
  and `place`. The output is deterministic, so this query is wrong on every run. Both smaller
  models got it right.
- **`people` and `place` are noisy.** Examples: `people` = "family", "बच्चे"; `place` = "park";
  "Delhi" missed. MVP search ignores both fields. A later people or place filter needs them
  to be better, or a check against the alias and place tables.
- **Disk.** `qwen2.5:7b` takes 4.7 GB in the Ollama cache. 31 GiB are free after removing the
  losers. `mistral:latest` (4.4 GB) was already installed and isn't ours, so it was left alone.
- **No prompt changes in phase B.** As decided in Q8, the phase A prompt was used unchanged for
  all three models.

### For M5

- Build the rewriter once per process with `OllamaRewriter(config.models.rewriter)` and call
  `rewrite(query)`. It never raises; on failure, `english == original == query`.
- Use `english` for the vector retriever, and both `english` and `original` for FTS (plan
  step 3). Devanagari `original` text won't match English captions, so for Hindi queries the
  vector side depends entirely on `english`.
- Memory at query time: SigLIP (about 1 GB) plus the rewriter (about 4.6 GB, held by Ollama for
  5 minutes). Don't search while the caption stage (about 4–6 GB) is running.
- The first query after 5 idle minutes pays a 5–9 s cold load.

### For M7

- Measure with and without the rewrite. #13 (Jaipur → Jodhpur) is a known wrong rewrite, worth
  including in the eval.
- `eval/rewrite_examples.yaml` holds hand-written `expect` strings that can be reused or
  extended.
