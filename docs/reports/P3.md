# P3 report: WhatsApp bot (official Cloud API)

Phase A (code and tests): 2026-10-21, branch `p3` in `.worktrees/p3`. Phase B (real messages)
is pending. It needs the user's Meta setup, the tunnel and a quiet machine.

## Summary

- `imgsearch serve` runs a FastAPI webhook server on 127.0.0.1 (`whatsapp.port`, 8765).
  - `GET /webhook` does Meta's verification handshake.
  - `POST /webhook` checks `X-Hub-Signature-256`, drops senders not on the allowlist and
    repeated message ids, queues the rest and returns 200 at once.
  - `GET /health` answers on the Mac only.
- One worker thread handles messages in order. `WhatsAppAdapter` (implements `ChatAdapter`)
  runs the search and replies through the Graph API.
  - Images: each is uploaded to `/{phone-number-id}/media`, then sent by media id. It sends
    the derivative, or the thumbnail when the pen drive is out.
  - Commands: `help`, `more` and `original N` (sent as a document, with a P1.6 fetch if the
    file was evicted).
- SigLIP loads on the first search and unloads after `whatsapp.idle_unload_s` (300 s)
  without messages (D21, review M5 N2).
- 43 new tests in `tests/test_whatsapp.py`, with the Graph API faked by `httpx.MockTransport`
  and fake retrievers. Full suite: **335 passed**; ruff format and check are clean.

Checked against Meta's current docs (2026-10-21), not memory:
- media upload: multipart `messaging_product`, `file`, `type`; returns `{"id"}`. JPEG/PNG up
  to 5 MB; documents up to 100 MB.
- image and document messages by `id`, with captions up to 1024 characters and a document
  `filename`.
- the webhook GET handshake (`hub.mode`, `hub.verify_token`, `hub.challenge`) and the
  `X-Hub-Signature-256` header (`sha256=` + HMAC-SHA256 of the raw body with the app secret).
- retries: failed deliveries are retried for up to 36 h, so deliveries must be deduplicated.
- the text-message webhook payload shape.

The examples use Graph API `v26.0`, which is the configured `whatsapp.api_version`.

## Changes from the plan

All are recorded in the plan's "Changes during build" (P3 entries).

- **`ChatAdapter` as built:** `send_images(to, results, first_rank=1)`. `first_rank` is
  optional, so callers of the protocol are unchanged; it numbers the captions of a `more`
  page. There is also `on_unsupported(sender)` for non-text messages.
- **Code layout:** a new package `imgsearch/chat/` (`whatsapp.py`, `bot.py`, `service.py`,
  `webhook.py`) and the command module `imgsearch/commands/serve.py`.
- **Config:** a new `whatsapp:` section. Secrets are read only from the environment or
  `.env`, and only by `serve`.
- **The host is fixed in code**, not config: 127.0.0.1.
- **Dependencies:** `fastapi` and `uvicorn` are declared directly. Both were already in
  `uv.lock` through `mlx-vlm`; the lock diff only adds the two declarations, and no versions
  changed. `uvicorn` was "already present" only as a transitive dependency. I declared it
  because `serve` imports it.

## Flags

### For phase B

- **Paging is capped by `per_retriever_k`.** A search returns at most `per_retriever_k` (10)
  results per retriever. With `default_signals: [vector]`, `more` therefore gives one extra
  page (6–10), then "No more photos". Raising this would mean changing `Searcher` (fetch
  `max(k, per_retriever_k)`), which P1.7 is also changing, so I left it.
- **HEIC originals.** WhatsApp doesn't list HEIC as a supported document type. `original N`
  sends it as `image/heic` with its file name. Phase B should check that it arrives. If not,
  the fallback is `application/octet-stream`.
- **Deduplication is in memory** (the last 1,000 ids). If Meta redelivers a message after a
  restart, the bot answers it again. There is no age cut-off, so after a long outage, queued
  retries (up to 36 h old) all get answered.
- **The verify token is in the URL.** Uvicorn's access log is off for that reason.
  Cloudflare's own logs aren't under our control; the token only matters during setup.
- **`/health` through the tunnel.** It returns 404 when the request has a `CF-Connecting-IP`
  header. The README's named-tunnel config forwards only `^/webhook$`. A quick tunnel
  (`--url`) forwards every path, so the header check is the only guard there.
- **Rewrite timeout.** If Ollama is slow, a reply can take up to `models.rewriter.timeout_s`
  (30 s) plus the cold SigLIP load. The webhook still answers Meta at once.

### For later tasks

- **Telegram swap:** replace `GraphClient` and `webhook.py`. The command logic in `bot.py`
  only calls `send_text`, `send_image` and `send_document`.
- **Merge:** `config.py` (new `WhatsAppConfig` and the `whatsapp` field on `Config`) and
  `cli.py` (one line) are also touched by P1.6.1 on `main`. Expect small conflicts at merge
