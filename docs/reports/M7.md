# M7 report: eval harness, contact sheet and MVP baseline

2026-10-20 · **Done.** Phase A built the harness and the review sheet, and ran the eval once
on 42 draft queries. The user then confirmed 41 queries. Phase B ran the baseline on those
41, plus the `per_retriever_k` experiment. It wrote `docs/eval/baseline.md`,
`docs/mvp-summary.md` and the README "Evaluation" section.

## Summary

- **Code** lives in `imgsearch/eval/`; `eval/` keeps the data (`queries.yaml`, `runs/`).
  - `queries.py`: loader and validation.
  - `metrics.py`: pure metric functions.
  - `run.py`: ablations, the shared `Searcher`, the run folder.
  - `tables.py`: markdown tables.
  - `html.py`, `sheets.py`: the HTML sheets.
  - `main.py`: what the commands do.
- **Commands.**
  - `imgsearch eval` runs 7 configurations over the query set with one `Searcher` (N2).
    It writes `eval/runs/<timestamp>/`: `results.json`, `metrics.json`, `meta.json` (commit,
    dirty flag, query-file hash, models, Ollama version, timings), a copy of `config.yaml`,
    and `contact_sheet.html`.
  - `imgsearch eval-compare A B` prints two runs' overall metrics side by side.
  - `imgsearch eval-review` validates the query set and writes `eval/runs/query_review.html`.
- **Configurations:** vector, text and hybrid, each with and without the rewrite (`+rw`),
  plus `hybrid+rw no captions`. That last one uses the new `TextRetriever(conn,
  kinds=("ocr",))`; the default is all kinds.
- **Metrics:** hit@5, recall@5 (found in the top 5 ÷ min(5, expected)) and reciprocal rank
  within the top 5. Each is reported overall, by language and by type.
- **N1:** model loading is quiet in `search` and `eval`. transformers logs errors only, its
  progress bar is off, and the one torch "Redirects ... MacOs" logger is set to ERROR.
- **Checks.** `uv run pytest` passes: 215 tests, 31 of them new. Ruff is clean. Fakes only:
  a fake rewriter, fake retrievers and a fake searcher builder passed to `evaluate(...,
  build=...)`.

### First reading (to be confirmed on the baseline)

- **Vector + rewrite is the best configuration** (recall@5 0.97), ahead of hybrid + rewrite,
  the configuration `imgsearch search` uses (0.86). Text search lowers hybrid's score more
  often than it raises it.
- **Why hybrid loses: RRF rewards appearing in both lists.** Each retriever returns 50 of only
  130 photos, so almost every text match is also somewhere in the vector list. A photo at
  vector 15 + text 4 scores 1/75 + 1/64 = 0.029. That beats a photo ranked 1st by vector
  alone: 1/61 = 0.016. Generic caption words then decide the order:
  - `hi-kal-shaadi`: vector ranks the 3 party photos 1–3; hybrid has none of them.
  - `user-car`: "car" matches "parked cars" and scooter captions. Vector has the photo 4th;
    hybrid has it nowhere.
  - `user-wedding-dress`: "traditional attire" and "dressed" match other captions.
  - `hi-scooty`: "road" pulls in the pigeon photos.
- **The rewrite helps every retriever on Hindi and Hinglish.** Vector recall goes from 0.82
  to 0.93 on Hindi and 0.79 to 0.97 on Hinglish. Text only goes from 0.00 to 0.78 on Hindi.
  English is unchanged.
- **Wrong rewrites seen:**
  - `dv-pigeons` कबूतरों का झुंड → "flock of **parrots**" (vector still finds them).
  - `dv-jaipur-fort` जयपुर का किला → "**Jayaipur**'s fort". This is no longer "Jodhpur", but
    it's misspelt, so FTS misses "Jaipur".
  - `hi-green-dupatta` → "near the garden of the women's palace in hare dupatta". "Hare
    dupatta" (green scarf) is left untranslated.
  - `hi-kal-shaadi` → "previous year's wedding" (N3).
- **Captions:** removing them costs 0.03 recall@5 and 0.12 MRR on hybrid+rw. Whether they are
  worth ~64 h is answered in phase B, with the vector-only numbers in mind.

## Flags

- **The query set favours the vector signal.** The queries describe what the photos look
  like, which is what SigLIP matches, and the library is small (130). On this set vector + rw
  gets hit@5 = 1.00, so the eval can't show much more gain for vector. Text-in-image queries
  are where text search can add something, and there are only 8 of them.
- **`search.per_retriever_k = 50` is large for 130 photos** (38% of the library per list).
  This is what lets the "found by both" bonus dominate. Phase B can measure a smaller value.
  That would be a config change, not a code change.
- **The English rewrite adds words.** For example, "flock of pigeons on a road" became
  "a flock of ...", and "give me images of pigeons" became "images of pigeons". Recall is
  unaffected.
- `cli.py` is 211 lines, slightly over the ~200 "Should". The eval commands are 3 thin
  wrappers.

### Answers (details in `docs/mvp-summary.md`)

- **The eval runs end to end:** one command, 90 s.
- **Hinglish and Hindi work through the rewrite:** vector+rw hit@5 is 1.00 on both, against
  0.83 and 0.88 without it.
- **Search default:** the numbers favour vector+rw (0.98 against 0.87 recall@5). The caveat
  is that the set leans toward visual descriptions. I proposed the change but didn't make it.
- **Captions:** not justified by this eval. They add 0.02 recall@5 inside hybrid, and
  vector+rw, which uses no text at all, is best. P2 should do ingest → embed → ocr and leave
  captions optional.
- **16 GB:** search is about 6.8 GB (2.24 GB + Ollama 4.6 GB); captioning is 5.84 GB on its
  own. They fit one at a time. Disk is tighter: ~21 GB of derivatives for 40k photos against
  32 GiB free.
- **Failure patterns:**
  - The RRF "found by both" bonus.
  - Wrong rewrites (parrots, Jayaipur, untranslated "hare dupatta", "previous year's").
  - Handwriting.
  - Near-duplicate bursts.
  - Devanagari without the rewrite.
  - Place names without GPS.
  Each has example ids in the summary.
