## Phase A (2026-10-21)

**Phase A done (P1.8).** Places from GPS and place-aware search are built and tested on
branch `p1.8` (`.worktrees/p1.8`, commit `ee20e91`), rebased on main after the P3-T review.
Not merged. Nothing ran against the real DB or the pen drive.

- **Offline place data:** `imgsearch geo download` ran once and fetched GeoNames for India
  (18 MB) into git-ignored `data/geo/`, with sizes and SHA-256 in `MANIFEST.tsv`. No
  geocoding API is called; search reads only the DB.
- **`places` stage:** for each photo with GPS, the nearest city, district, state, country
  and landmark (within 1 km), using numpy only. It loads in 0.6 s and takes about 1 ms per
  photo. Runs in `update` after filename and in `imgsearch run places`; `status` shows GPS
  coverage.
- **Checked on typed coordinates:**
  - India Gate, Amber Fort and Baga Beach come back as landmarks.
  - Noida → Gautam Buddha Nagar, Uttar Pradesh. Mussoorie → Dehradun, Uttarakhand.
- **Search:** the rewriter's place counts only if a photo was taken there.
  - Jaipur, जयपुर, Bangalore/Bengaluru and Gurgaon/Gurugram resolve. "park", "sofa" and
    "home" are ignored.
  - Results keep photos from that place (a state includes its cities) or whose
    text names it.
  - Works with the date filter. If nothing matches, the place is dropped first, then the
    date, and the CLI and bot say so.
  - `--no-place-filter` on `search` and `eval`.
- **Results show date and place** in the CLI and in bot captions ("Amber Fort, Amer,
  Jaipur, Rajasthan").
- **Checks:** 540 tests pass (54 new, synthetic GeoNames files), ruff clean, no new
  dependencies.
- **Docs:** README "Places from GPS (P1.8)" (with GeoNames credit and privacy note), plan D22
  and "Changes during build", `docs/reports/P1.8.md`.

**Your question, restaurants (e.g. Barbeque Nation):** no. GeoNames has only 17 restaurants
for all of India and no Barbeque Nation, so such a photo gets its area (city, district,
state), not the restaurant. Those photos are still found by text in the photo (logo, menu,
bill) and by date. Naming restaurants would need OpenStreetMap data, which is a separate,
larger task.
