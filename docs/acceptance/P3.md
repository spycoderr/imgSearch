# P3 acceptance criteria: WhatsApp bot (official Cloud API)

Blocking unless marked "Should". Design: plan D11, D13, D21, P3 row; interfaces `ChatAdapter` and `search()`.
Phase A (code + tests) runs in a worktree now; phase B (real messages) needs the user's Meta setup, a public
HTTPS URL, and a quiet machine (no caption run, since search needs ~7 GB).

## Security and secrets

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | Secrets only in the git-ignored `.env`: access token, phone-number id, app secret, webhook verify token, allowed sender numbers. `.env.example` gets placeholders; nothing in commits or logs | `git grep`; read logs |
| 2 | Webhook verification (`GET` with `hub.verify_token`) and **signature check** on every `POST` (`X-Hub-Signature-256`, HMAC-SHA256 with the app secret, constant-time compare); a bad signature gets 401 and is not processed | Tests |
| 3 | **Sender allowlist**: messages from numbers not in the list are ignored (logged by count, not content), with no reply | Tests |
| 4 | The server listens on localhost only; the public URL comes from the tunnel. No other routes exposed; no directory listing; no original files served | Read code; test |
| 5 | Message contents and photos are not logged; logs hold message ids, timings and counts only | Read code |

## Behaviour

| # | Criterion | How to verify |
| --- | --- | --- |
| 6 | A text message runs `search()` once (the same default as the CLI) and replies with the top results as **images**: the resized derivative (never the original), each with a short caption line (rank, date, short caption if any). Default 5, configurable | Tests with a fake Graph API |
| 7 | Images are uploaded to the Graph API media endpoint and sent by media id (no public links to photos) | Test |
| 8 | Replies within seconds: the webhook returns 200 immediately and the search runs in the background (Meta retries slow webhooks); duplicate deliveries of the same message id are processed once | Tests |
| 9 | Pen drive unplugged: falls back to the thumbnail and says full-size images are unavailable | Test |
| 10 | Rewrite fallback / no results / errors produce a short text reply, never a stack trace | Tests |
| 11 | Simple commands: `help`; `more` (next 5 for the last query); `original N` sends the full original for result N **only if** it is on the drive or fetchable (P1.6 fetch), as a document, with a size limit check | Tests |
| 12 | Models follow D21: the service loads SigLIP on first use and unloads it after an idle timeout from config; Ollama keep-alive unchanged | Test with fakes; observe RSS in phase B |
| 13 | The adapter implements `ChatAdapter` (`on_message`, `send_images`); the HTTP layer is thin (FastAPI) so Telegram could replace it | Read code |
