# M2 acceptance criteria: embedding stage and vector retriever

Blocking unless marked "Should". Wave rules (worktree, phase A/B) are in the task prompt and `docs/reviews/wave-M2-M6.md`.

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | `SiglipEmbedder` implements `Embedder` (`embed_images`, `embed_text`); model name, dim and device come from `config.models.embedder` | Read code; grep for model names in `imgsearch/` |
| 2 | Text is tokenized the way the model card requires (SigLIP: `padding="max_length"`, `max_length=64`); checked against the model card, not memory | Read code and report |
| 3 | Image and text vectors are L2-normalized float32 of length `dim`; a wrong length raises | Test |
| 4 | `embed` stage: `requires=["ingest"]`, version from config, reads the derivative (never the original), loads the model in `load()`, frees it in `unload()` (incl. `torch.mps.empty_cache()`) | Read code, test with a fake embedder |
| 5 | Vectors stored in `embeddings` keyed by `(image_id, model)` via `sqlite_vec.serialize_float32`; re-run replaces, never duplicates | Test |
| 6 | `VectorRetriever.retrieve(q, k)` embeds `q.english`, ranks by `vec_distance_cosine` over rows for the configured model only, returns `Candidate`s with rank 1 = best and signal `"vector"` | Test with hand-made vectors |
| 7 | `imgsearch search-vec "..."` prints top k with rank, score and original relpath | Run it |
| 8 | Real run (phase B): 130 done, 0 failed; second run processes 0 | `imgsearch status` |
| 9 | Real queries "a plate of food", "a dog", "people at a beach" (or similar fitting the photos) return plausible images; the report lists the top 3 relpaths for each | Report; reviewer opens the images |
| 10 | Bumping `stages.embed` re-embeds only that stage | Status before/after (report) |
| 11 | Benchmark in `docs/benchmarks.md`: seconds per image, model load time, peak memory, text-query latency | Read |
| 12 | Tests, ruff pass; no hacks; no new dependencies without a stated reason | Run; grep |
| 13 | Report `docs/reports/M2.md`; README section; plan changes recorded | Read |
