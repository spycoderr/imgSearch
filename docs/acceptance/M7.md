# M7 acceptance criteria: eval harness, contact sheet, MVP baseline

Blocking unless marked "Should". M7 runs in two phases: **A** builds the harness and drafts the
query set, then stops for the user to confirm the queries; **B** runs the eval on the confirmed set.
It also closes review notes N1 and N2 from `docs/reviews/M5.md`.

## Query set (`eval/queries.yaml`)

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | 30–40 queries, each `{id, query, language, type, expected_image_ids, note}`. `language`: english, hinglish, hindi. `type`: scene, object, text, place, hard | Read file |
| 2 | Mix: at least 12 English, 10 Hinglish, 6 Devanagari; at least 6 text-in-image; at least 4 `hard` (including जयपुर/Jaipur, "kal wali shaadi", a handwriting query and a near-duplicate set) | Loader prints counts |
| 3 | **Queries are written from looking at the photos, not from reading their captions or OCR text.** Otherwise the eval measures how well a query copies a caption. The draft step must not open `captions`, `ocr` or `text_fts` | Report states the method; reviewer spot-checks wording against captions |
| 4 | `expected_image_ids` are image ids (hashes) that exist in the DB; every visually matching photo is listed (all photos of a burst count) | Loader validates ids; reviewer checks the review sheet |
| 5 | The loader rejects unknown ids, unknown language/type values, empty expected lists and duplicate query ids, with a clear error | Tests |
| 6 | Phase A ends with a **query review sheet** (HTML: each query with its expected thumbnails) for the user. The set counts as confirmed only after the user says so; changes are made in the YAML | User confirmation recorded in the hand-back |

## Metrics

| # | Criterion | How to verify |
| --- | --- | --- |
| 7 | Per query: **hit@5** (any expected image in the top 5), **recall@5** (expected found in top 5 ÷ min(5, number expected)) and **reciprocal rank** of the first expected image | Read code; unit tests with fixed rankings |
| 8 | Reported overall, by language and by type | Report |
| 9 | Pure functions, tested on hand-made rankings, including no hits, all hits and more expected than 5 | Tests |

## Runs, contact sheet and reports

| # | Criterion | How to verify |
| --- | --- | --- |
| 13 | One command (e.g. `imgsearch eval`) runs every configuration and writes a run folder under `eval/runs/<timestamp>/` (git-ignored): per-query results JSON, metrics, the git commit, and a copy of `config.yaml` | Run it; inspect folder |
| 14 | Runs can be compared later: a small command or flag prints the metric table for two run folders side by side | Run it |
| 15 | Contact sheet: one self-contained HTML file per run (thumbnails embedded, opens offline). Per query: the query, the rewrite, top 5 thumbnails with per-signal ranks and fused score, the expected images, hits marked, missed expected images shown. A summary table at the top | Open it |
| 16 | The contact sheet and runs stay local; they contain personal photos and are never committed or published | `git status`; `.gitignore` |
| 17 | Model load warnings and progress bars are quiet during eval and `search` (N1), without hiding real errors | Run it |
