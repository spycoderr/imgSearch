# P1.7 acceptance criteria: file names, dates, and smarter merging

Blocking unless marked "Should". Goal: answer queries whose answer lives in a **file name**, a **folder name**
or a **date**, without losing what vector search already does well. Measured on the 53-query eval (41 original
+ 12 user-written `u2-*` queries on phone photos, see `eval/manual-queries.txt`).

## Starting facts (2026-10-21)

- Default search is vector + rewrite (`search.default_signals: [vector]`); hybrid (`vector,text`) is opt-in.
- 1,244 of 1,441 photos have an EXIF date (`taken_at`); 197 don't (mostly screenshots). The importer keeps
  the phone's file mtime on the copy, but the DB doesn't store it.
- The phone subfolder (Screenshots, WhatsApp, Adobe Scan Exports, Reddit, ...) is lost at import: originals
  are filed under `YYYY/MM/`. Captions exist for only the 130 MVP photos.
- File names carry meaning for documents and screenshots: `Signature Nilabh black_1 (1).jpg`,
  `Ultrasound report Kaushlya devi_1.jpg`, `Screenshot_20260327-171258_Gmail.png`, `StarRail_Image_*.jpg`.

| # | Criterion | How to verify |
