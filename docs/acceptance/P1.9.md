# P1.9 acceptance criteria: less memory while searching

Blocking unless marked "Should". Goal: make a search, from the bot or the CLI, use as little RAM as possible
without making results worse. The user chose search-time memory as the target (2026-10-24). Run it after P6.1
and P5, so the measurements include their changes to search.

## Starting facts (2026-10-24, `docs/benchmarks.md`)

| While searching | Memory |
| --- | --- |
| Search process (SigLIP 2, torch on mps), peak footprint | 2.20–2.23 GB |
| Ollama rewriter `qwen2.5:7b`, context 4096 | 4.6 GB |
| Total | ~6.8 GB |
| Idle bot (models unloaded) | ~110 MB RSS |

M6 also measured `qwen2.5:3b` at 1.9 GB and `gemma3:4b` at 2.2 GB (speed only, not recall on today's eval).

## 1. Measure first

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | One repeatable script measures, for a fixed set of ~10 queries: peak memory footprint of the search process (incl. Metal), Ollama's resident memory, cold and warm latency. Run it before any change | `docs/benchmarks.md` |

## 2. Candidates (try each, keep what passes rule 6)

| # | Criterion | How to verify |
| --- | --- | --- |
| 2 | **Query side loads the text tower only.** Search embeds text, never images, so SigLIP's vision weights shouldn't be loaded there (stages that embed images are unchanged). Vectors must match the full model's to float tolerance | Test |
| 3 | SigLIP weights in float16 on mps for queries, if vectors stay within tolerance of float32 (cosine ≥ 0.999 on the eval queries) | Test; report |
| 4 | Smaller rewriter: compare `qwen2.5:7b` with `qwen2.5:3b`, `gemma3:4b` and any other small model already in Ollama, on the full eval (Hindi and Hinglish queries reported separately), plus a lower `num_ctx` (the rewrite prompt's real size + margin) | `docs/eval/baseline-p1.9.md` |
| 5 | Should: no other memory leaks: the bot's RSS after 50 searches and an idle unload is back within 50 MB of its start | Report |
