# M3 acceptance criteria: OCR stage and text retriever

Blocking unless marked "Should". Wave rules are in the task prompt and `docs/reviews/wave-M2-M6.md`.

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | `AppleVisionOCR` implements `OCREngine.read(path) -> str` via `ocrmac`, English, "accurate" level; settings in `config.models.ocr` | Read code |
| 2 | Text lines are joined in reading order, one line per `\n` | Test with a generated image containing two lines |
| 3 | `ocr` stage: `requires=["ingest"]`, version from config, reads the derivative, writes only through `store.text.save_ocr` | Read code |
| 4 | An image without text stores `""` and is `done`, not `failed` | Test |
| 5 | `TextRetriever` searches **all** of `text_fts` (OCR and captions, so M4 needs no retriever change), ranked by `bm25`, one `Candidate` per image (best row), signal `"text"` | Test with rows of both kinds |
| 6 | User text is made safe for FTS5 `MATCH`: words extracted, each quoted, joined with `OR`. Queries containing `"`, `-`, `:`, `*`, `(`, `AND`, `NEAR` or Devanagari never raise | Tests for each |
| 7 | `retrieve` searches both `q.english` and `q.original` (dedupe by image, keep best rank) | Test |
| 8 | `imgsearch search-text "..."` prints top k with rank, score, relpath and a text snippet | Run it |
| 9 | Real run (phase B): 130 done, 0 failed; the report lists how many images have non-empty text | `imgsearch status`; SQL |
| 10 | At least 3 real text-in-image queries (a word visible on a menu, sign or screenshot) return that image in the top 3; listed in the report | Report; reviewer checks |
| 11 | The panorama `IMG_20171115_132546.jpg` OCR output is reported (readable or not) | Report |
| 12 | Benchmark: seconds per image, peak memory | `docs/benchmarks.md` |
| 13 | Tests, ruff pass; no hacks; report `docs/reports/M3.md`; README section | Run; read |
