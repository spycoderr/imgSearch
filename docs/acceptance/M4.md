# M4 acceptance criteria: caption stage

Blocking unless marked "Should". Wave rules are in the task prompt and `docs/reviews/wave-M2-M6.md`.

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | `MlxCaptioner` implements `Captioner.caption(path) -> str` with `mlx-vlm`, using the API of the **installed** version (0.7.9), checked in its source, not from memory | Read code and report |
| 2 | Model name, prompt, `max_tokens` and the image size limit come from `config.models.captioner` | Read config and code |
| 3 | The prompt asks for 1–2 English sentences plus any visible text verbatim; greedy decoding (temperature 0) | Read config |
| 4 | Images are resized for the VLM (e.g. long edge ≤ 1024) so the 6203 px panorama and 2364 px photos don't blow up token count or memory | Read code; benchmark shows peak memory |
| 5 | Output is cleaned only of chat-template artifacts (special tokens, leading "Caption:"), nothing else | Test with a fake model output |
| 6 | `caption` stage: `requires=["ingest"]`, version from config, reads the derivative, writes only through `store.text.save_caption` with the model name | Read code |
| 7 | `unload()` frees the model (drop references, `mx.clear_cache()` or the installed equivalent); peak memory reported | Read code; report |
| 8 | Real run (phase B): 130 done, 0 failed; second run processes 0 | `imgsearch status` |
| 9 | Report includes 10 sample captions (mixed: food, text-heavy, people, scenery) for the reviewer to judge | Report |
| 10 | Benchmark: model load time, seconds per image (median and max), peak memory, and a projection for 40k images | `docs/benchmarks.md` |
| 11 | Report gives a recommendation: caption everything, caption only text-bearing images, or skip captions for the bulk run, with reasons from the numbers | Report |
| 12 | Captions are findable by text search (`text_fts` rows with kind `caption`) | SQL check |
| 13 | Tests, ruff pass; no hacks; report `docs/reports/M4.md`; README section | Run; read |
