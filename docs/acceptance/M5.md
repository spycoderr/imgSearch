# M5 acceptance criteria: hybrid search, fusion, `search()` and CLI

Blocking unless marked "Should". M5 also wires in the M6 rewriter and closes review items W1, W3
and W4 from `docs/reviews/wave-M2-M6-close.md`.

## Fusion

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | `rrf_fuse(rankings, k)` is a plain function: score = Σ 1 / (k + rank) over the rankings an image appears in; `k` from `config.search.rrf_k` | Read code |
| 2 | Ties in fused score are broken deterministically (by best single rank, then `image_id`) | Test |
| 3 | Unit tests with fixed rankings: one list only, two lists that agree, two that disagree, an image in only one list, ties, empty input | Tests |

## `search()` and `Result`

| # | Criterion | How to verify |
| --- | --- | --- |
| 4 | One entry point for every adapter, built once and reused across queries, so models load once (the M7 eval calls it many times) | Read code |
| 5 | Query flow as in the plan: rewrite → vector retriever on `english` → text retriever on `english` + `original` → RRF → top `k` (default `search.top_k`); each retriever asked for `search.per_retriever_k` | Read code; test with fakes |
| 6 | Switches for the M7 ablations: rewrite on/off, and which signals to use (vector, text, both). Plain parameters, not a plugin system | Read code; tests |
| 7 | `Result` carries image id, derivative and thumbnail paths, caption, the fused score, and per-signal (rank, score). Any change to `Result` is recorded under "Changes during build" | Read code and plan |
| 8 | The rewriter's output is kept with the results, so CLI and eval can show what was searched | Read code |
| 9 | If Ollama is down, search still works on the raw query (rewriter fallback), and the CLI says the rewrite was skipped | Test with a failing fake; real check with Ollama stopped is optional |
| 10 | Unit tests use fakes for embedder, rewriter and retrievers. No real models, no monkeypatching | Read tests |
