# M6 acceptance criteria: query rewriter (built early, wired into `search()` in M5)

Blocking unless marked "Should". Wave rules are in the task prompt and `docs/reviews/wave-M2-M6.md`.

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | `OllamaRewriter` implements `QueryRewriter.rewrite(query) -> ParsedQuery`; model name, URL, timeout and prompt come from `config.models.rewriter` | Read code |
| 2 | Calls Ollama's chat API over `httpx` with JSON-schema structured output and temperature 0 (checked against current Ollama API docs) | Read code |
| 3 | The response is validated with a pydantic model (`english`, `original`, `people`, `date_range`, `place`); `original` is always set to the user's exact input by code, not trusted from the model | Test |
| 4 | Any failure (connection error, timeout, non-JSON, schema mismatch, empty `english`) falls back to `ParsedQuery(english=query, original=query)`; the fallback is logged, not silent | Tests with a fake HTTP transport (`httpx.MockTransport`), no monkeypatching |
| 5 | The prompt forbids inventing facts and says English queries return unchanged | Read prompt |
| 6 | `imgsearch rewrite "..."` prints the parsed JSON and the time taken | Run it |
| 7 | Real check against Ollama: 10 Hinglish and 5 Devanagari queries plus 5 English queries, stored in `eval/rewrite_examples.yaml`; the report shows each input and output | Report; reviewer judges |
| 8 | English queries come back unchanged (or trivially normalized) in at least 4 of 5 | Report |
| 9 | Latency: median and max seconds per query, first call (cold) vs warm | `docs/benchmarks.md` |
| 10 | The model stays in memory only as long as Ollama's default keep-alive; the report states the resident memory (`ollama ps`) | Report |
| 11 | No change to `search()` or retrievers (that's M5) | `git diff` |
| 12 | Tests, ruff pass; no hacks; report `docs/reports/M6.md`; README section | Run; read |
