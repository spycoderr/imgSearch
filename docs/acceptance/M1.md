# M1 acceptance criteria: local source and ingest stage

The reviewer checks every item below before M1 counts as done. Each item says how to verify it.
An item that fails blocks completion; "Should" items are flagged but don't block.

Test data: 130 JPGs in `data/originals` (2016–2019, vivo phone). 129 have an EXIF date, none has
GPS, 2 have an EXIF orientation other than 1. A checksum and mtime of every original was recorded
before M1 started.

## 1. Originals untouched (highest priority)

| # | Criterion | How to verify |
| --- | --- | --- |
| 1.1 | Every original is byte-identical, with the same mtime, after M1 | Compare against the pre-M1 checksum/mtime record |
| 1.2 | `data/originals` holds the same 130 files and nothing new (no derivatives, temp files, `.DS_Store` written by code) | `ls data/originals \| wc -l` |
| 1.3 | Originals are only ever opened `"rb"`; no code path writes, moves or re-saves them | `grep -rn "open(" imgsearch/sources imgsearch/stages` and read |
| 1.4 | Tests never use `data/originals`; all fixtures live in `tmp_path` | Read tests |

## 2. Source and register step

| # | Criterion | How to verify |
| --- | --- | --- |
| 2.1 | `LocalFolderSource` implements `ImageSource` (`scan`, `open`) and walks folders recursively | Read code, test |
| 2.2 | Only `.jpg .jpeg .png .heic .heif` (any case) are yielded; `.mov .aae .json .zip` and hidden files (`.DS_Store`, `._*`) are skipped | Test exists |
| 2.3 | Image id is the SHA-256 of the file bytes, read in chunks (not the whole file in memory) | Read code |
| 2.4 | `orig_relpath` is relative to `originals_root`; no absolute path in `images` | `sqlite3 data/imgsearch.db "select orig_relpath from images limit 3"` |
| 2.5 | Two files with the same bytes produce one row (first path kept) | Test exists |
| 2.6 | An unreadable file is counted and reported, and doesn't stop the run | Test exists |
| 2.7 | Re-hashing on every run is noted as a P2 item (plan doc or README) | Read docs |

## 3. Ingest stage

| # | Criterion | How to verify |
| --- | --- | --- |
| 3.1 | `ingest` is a normal `Stage` run by `run_stage`; version from `config.stages["ingest"]`; no ingest special case in the runner | Read code; `git diff` shows the runner unchanged or trivially changed |
| 3.2 | EXIF orientation is applied before resizing; width/height are stored after orientation | Test with a rotated image |
| 3.3 | Derivative: JPEG, long edge 2048, never upscaled | Test; spot-check a real derivative's size |
| 3.4 | Thumbnail: JPEG, long edge 256 | Test |
| 3.5 | Files go to `derivatives/<id[:2]>/<id>.jpg` and `thumbs/<id[:2]>/<id>.jpg` under `derivatives_root`; DB paths are relative to `derivatives_root` | `select derivative_path, thumb_path from images limit 3` |
| 3.6 | `taken_at` comes from DateTimeOriginal, then DateTime; ISO 8601; NUL padding stripped; invalid dates become NULL; file mtime never used | Tests for normal, NUL-padded, invalid and missing |
| 3.7 | GPS converts to signed decimal degrees (S and W negative); NULL when absent | Test with synthetic GPS EXIF |
| 3.8 | `phash` is filled (hex) from the oriented image | Query the DB |
| 3.9 | HEIC is supported via `pillow_heif` (tested, or a clear stated reason if it can't be tested) | Test or report |
| 3.10 | A corrupt image is recorded `failed` with its error; the others finish `done` | Test exists |

## 4. CLI and real run

| # | Criterion | How to verify |
| --- | --- | --- |

| 4.3 | Second run: 0 new, 0 processed | Run it again |

| 4.5 | Every `derivative_path` and `thumb_path` in the DB points to an existing file | Small script |
