# P1.5-A acceptance criteria: import from the inbox, storage on the pen drive

Blocking unless marked "Should". Design: plan D18, D20, P1.5; CLAUDE.md "Originals are read-only".

## Storage layout (D18)

| # | Criterion | How to verify |
| --- | --- | --- |
| 1 | Config has separate roots: `originals_root` and `derivatives_root` on the pen drive (`$IMGSEARCH_STORAGE_ROOT/originals` and `/derivatives`, set in `.env`), a new `thumbs_root` and `db_path` on the Mac, and a list of inbox folders (`data/inbox/phone` to start) | Read `config.yaml` |
| 2 | Thumbnail paths are stored relative to `thumbs_root`; existing rows are moved over by a numbered migration (no edits to applied migrations), and every stored path still resolves | SQL + script check |
| 3 | A small helper says whether a root is available: for a path under `/Volumes/<name>`, the volume must be mounted (`os.path.ismount`). Every command that needs the pen drive checks it first and fails with a clear message ("pen drive not mounted: …") | Tests; run with the drive ejected (optional) |
| 4 | `imgsearch search` still works with the pen drive missing (vectors in the DB, thumbnails on the Mac) and says that full-size images are unavailable | Test with a missing root |
| 5 | The DB never moves to the pen drive; config validation rejects a `db_path` under `/Volumes/` | Test |

## Import (`imgsearch import`)

| # | Criterion | How to verify |
| --- | --- | --- |
| 6 | Scans each inbox recursively for image files (same rules as `LocalFolderSource`: image suffixes, hidden and Syncthing temp files skipped), and skips files modified in the last 60 s (still being written) | Tests |
| 7 | Hash first. A hash already in `images` is a duplicate: counted, and the inbox file is removed | Test |
| 8 | New photos go to `originals_root/YYYY/MM/<original name>`, with the date from EXIF (DateTimeOriginal, then DateTime), else the file's mtime (Syncthing keeps the phone's mtime); a name clash with different content gets a `-<hash8>` suffix; an existing file is never overwritten | Tests |
| 9 | Copy safely: write to a temp name in the target folder, flush and fsync, re-hash the copy, compare, then rename. Only after that: insert the `images` row (relpath relative to `originals_root`), and only after the row is committed, delete the inbox file | Read code; tests incl. a simulated hash mismatch (nothing registered, inbox kept) |
| 10 | A failure on one file is reported and doesn't stop the others; the inbox file is kept | Test |
| 11 | Prints counts: imported, duplicates, skipped (too new), failed, with paths for failures; non-zero exit if any failed | Run it |
| 12 | Re-running with nothing new does nothing | Test |
