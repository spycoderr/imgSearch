# M0 acceptance criteria: scaffold, config, schema, stage framework

The reviewer checks every item below before `m0-scaffold` is merged. Each item says how to verify it.
An item that fails blocks the merge; "Should" items are flagged but don't block.

## 1. Project and layout

| # | Criterion | How to verify |
| --- | --- | --- |
| 1.1 | Package code lives in `imgsearch/` with `sources/ stages/ models/ store/ search/ cli.py` | `ls imgsearch` |
| 1.2 | `config.yaml`, `tests/`, `eval/`, `docs/` are at the project root, not inside the package | `ls` |
| 1.3 | `uv run imgsearch` works through `[project.scripts]` and a build system in `pyproject.toml` | `uv run imgsearch --help` |
| 1.4 | No new dependencies unless needed; each added one has a reason in the report | `git diff main -- pyproject.toml` |

## 2. Config

## 3. Database schema and migrations

| # | Criterion | How to verify |
| --- | --- | --- |
| 3.1 | Tables `images`, `stage_status`, `embeddings`, `ocr`, `captions`, `text_fts` exist with the columns from the prompt | `sqlite3 data/imgsearch.db .schema` |
| 3.2 | `embeddings` is a plain table keyed by `(image_id, model)`, not a virtual table | `.schema` |
| 3.3 | `text_fts` is FTS5 with `image_id` and `kind` unindexed | `.schema` |
| 3.4 | Migrations are numbered `.sql` files tracked with `PRAGMA user_version`; opening the DB twice applies them once | Test exists |
| 3.5 | `connect(config)` loads sqlite-vec (`select vec_version()` works) | Test exists |
| 3.6 | No table name conflicts with the plan's reserved names (`faces`, `persons`, `dup_groups`, `events`, ...) | `.schema` |
