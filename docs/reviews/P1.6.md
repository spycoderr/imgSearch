## `/code-review` findings (medium), triaged

| # | Finding | Decision |
| --- | --- | --- |
| R1 | Errors other than `StoreUnavailable` in `upload_db` (expired credentials, 403, a version-id or check error) escape `upload()`, so `update` crashes **before** ingest/embed/ocr | **Fix (P1.6.1).** Any upload failure is reported and indexing continues (plan rule) |
| R2 | Import treats a duplicate whose original was **evicted** as a failure, so a re-synced or Takeout copy of an evicted photo fails on every run | **Fix.** A duplicate with a verified S3 copy is a normal duplicate |
| R3 | Bumping the ingest version fails for every evicted image (its original isn't on the drive) | **Fix.** Stages that read the original fetch it first (through `fetch`), and the cache cap applies again on the next `evict` |
| R4 | `fetch`, `evict` and `restore-check` show a raw traceback when S3 is unreachable mid-run; `evict` stops without a summary | **Fix.** Clean message and exit 1; `evict` prints what it did before stopping |
| R5 | `s3.bucket` / `s3.profile` are required for **every** command, so search/status fail offline or without the two env vars | **Fix.** Only commands that use S3 need them |
| R6 | `restore-check` crashes on a missing or undecryptable DB copy and loses the per-original results | **Fix** (report it as a failure) |
| R7 | `update` uploads the DB copy before indexing, so the cloud DB copy never has the current run's index | **Fix.** Originals upload early; the DB copy uploads at the end of `update` |
| R8 | `restore-check` prints "N of {requested}" instead of "N of {sampled}" | **Fix** (trivial) |
| R9 | `status` stats every original on the drive (slow at 40k on exFAT) | **Defer to P2**: track the size in the DB |
| R10 | `fetch` checks `dest.exists()` then `os.rename` (rename replaces on POSIX); suggested `os.link` | **Rejected:** exFAT has no hard links, so `os.link` would fail on the pen drive. Single user, single process; the check-then-rename window is acceptable, as for import |
