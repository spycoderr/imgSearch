## Open items for M1.1 (fix now)

Each changes the derivatives, so bump `stages.ingest` to `"2"` and re-run ingest.

| # | Item | Fix |
| --- | --- | --- |
| R1 | Transparent PNGs (screenshots, logos) become black backgrounds after `convert("RGB")`, which hides dark text from OCR | Composite images with alpha (RGBA, LA, P with transparency) onto white before converting |
| R2 | The source ICC profile is copied onto the RGB output even when the source was CMYK or another mode, giving wrong colours | Keep the ICC profile only when the source mode is already RGB |
| R3 | Malformed GPS (a scalar instead of a 3-tuple, a bad ref) raises and fails the whole image, which blocks every later stage. (0, 0) "no fix" is stored as a real position | Any malformed GPS value gives (None, None). Treat exactly (0, 0) as None. Reject \|lat\| > 90 or \|lon\| > 180 |
| R4 | `taken_at` mixes offset-aware and naive strings, which breaks date sorting and range filters later | Always store naive local time (`YYYY-MM-DDTHH:MM:SS`); drop the offset. Users query by local time ("Diwali evening") |
| R5 | Panorama `IMG_20171115_132546.jpg` (6656×544) shrinks to ~167 px tall, too small for OCR; tall phone screenshots shrink too | Cap the derivative by pixel area instead of long edge: downscale only above 2048×1536 ≈ 3.1 MP, keeping the aspect ratio. 4:3 photos stay 2048×1536; panoramas and long screenshots keep readable detail. Record the change to D8 |
| R6 | Derivatives take ~0.58 MB each, about 24 GB for 40k photos against 39 GB free | Lower derivative JPEG quality from 90 to 85. Report the new size per image |

## Rejected

- *Stage should read originals through `ImageSource.open`:* the source finds new files. Reading by
  `originals_root / orig_relpath` is the plan's design (D9), and later sources deliver into the
  originals folder (P4 mover).
- *CLI imports the ingest stack on every command:* a small startup cost; the search command will load
  heavier models anyway.
- *Tests chmod files under `originals_root`:* that root is a pytest `tmp_path`, not the real
  folder. The rule protects the user's photos, not temp fixtures.
